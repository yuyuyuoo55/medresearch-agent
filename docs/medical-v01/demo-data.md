# Demo 数据与知识库资料

当前已有 `docker/mysql/mysql.sql`：drugs（50）、inventory（150）、sales_records（100），数量来自初始化脚本声明，不代表本轮实时数据库计数。库存、销售、客户与批准文号为教学模拟数据；产品字段含药品名称/描述，不能作为医学权威来源。

保留现有数据和只读权限，不覆盖、不重新导入、不重建卷。脚本依赖空库自增ID顺序，不应直接在已有库重放。现有成功报告中的阿托伐他汀钙片（立普妥）三批库存为1000/2500/4000，手工和为7500；这是历史报告的核算示例，不是本轮数据库查询结论。

最小测试建议（有Agent调用时须另授权）：
- 产品筛选：按真实therapeutic_area值筛选并核对返回产品；预期以人工SELECT为准。
- 库存：按drug_id汇总quantity_on_hand，核对各批次和；不得混用销售记录行数。
- 销售：按明确日期范围汇总quantity_sold/total_amount，核对数量×单价；现有库存为快照，没有进货/出库账本，不能宣称可由销售重建库存。

本轮不换数据，避免为收尾引入迁移。新增一份非临床业务规则资料 `demo-docs/库存与销售分析规则.md`，仅供产品演示。推荐导入开发者现有用于本项目的RAGFlow知识库（名称未核验，不虚构名称）。人工先确认目标Dataset/Chat和已有产品对应关系，再上传、解析、检查检索结果；本轮未调用上传、删除、重建接口。RAGFlow全链路未验收。
